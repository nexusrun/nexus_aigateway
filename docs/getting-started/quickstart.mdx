This guide follows the repository's current build and runtime defaults. It runs
the gateway with SQLite, the embedded dashboard, and one provider configured
through environment variables.

## Prerequisites

- Go 1.27 or later
- Node.js and npm for the dashboard and documentation build
- At least one provider API key

## 1. Clone and configure

```bash
git clone https://github.com/nexusrun/nexus_aigateway.git
cd nexus_aigateway
cp .env.template .env
```

Edit `.env` and make the local storage and authentication settings explicit:

```env
STORAGE_TYPE=sqlite
SQLITE_PATH=data/aigateway.db
AIGATEWAY_MASTER_KEY=replace-with-a-long-local-secret
OPENAI_API_KEY=your-provider-key
```

Use the environment variable for the provider you selected. The gateway
discovers configured providers from their documented `*_API_KEY` variables.
See [Providers](/providers/overview) for provider-specific variables and model
support.

<Warning>
  The gateway starts without a master key for local experimentation, but that
  is unauthenticated mode. Always set `AIGATEWAY_MASTER_KEY` before exposing
  the gateway beyond your local machine.
</Warning>

## 2. Build and start

Build the dashboard, then start the Go gateway:

```bash
make frontend
make run
```

The dashboard is embedded into the binary. To serve the full product
documentation locally at `/docs`, export it once before starting:

```bash
make docs
make run
```

The documentation export is generated into `bin/docs` and is not source code.
If you skip `make docs`, the gateway still builds and serves a small fallback
page at `/docs`.

## 3. Open the app

| Surface | URL |
| --- | --- |
| Dashboard | `http://localhost:8080/admin/dashboard` |
| Product documentation | `http://localhost:8080/docs` |
| Model inventory | `http://localhost:8080/v1/models` |
| OpenAI-compatible API | `http://localhost:8080/v1` |
| Swagger UI | `http://localhost:8080/swagger/index.html` |

The dashboard and admin API are enabled by default. Requests use the master key
as a bearer token until you create managed API keys in the dashboard.

## 4. Send a request

First inspect the models exposed by the configured provider:

```bash
curl http://localhost:8080/v1/models \
  -H "Authorization: Bearer replace-with-a-long-local-secret"
```

Use one of the returned model IDs in an OpenAI-compatible request:

```bash
curl http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer replace-with-a-long-local-secret" \
  -d '{
    "model": "openai/gpt-4o-mini",
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'
```

The provider-qualified model name is an example. Use the exact ID returned by
`GET /v1/models`; model availability depends on the provider account and its
configured model filters.

## 5. Use an SDK

OpenAI-compatible clients use `/v1` as their base URL:

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8080/v1",
    api_key="replace-with-a-long-local-secret",
)

response = client.chat.completions.create(
    model="openai/gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hello in one sentence."}],
)

print(response.choices[0].message.content)
```

For Anthropic-compatible clients, use the gateway root as the base URL. The
client sends requests to `/v1/messages`:

```python
import anthropic

client = anthropic.Anthropic(
    base_url="http://localhost:8080",
    api_key="replace-with-a-long-local-secret",
)

message = client.messages.create(
    model="anthropic/claude-sonnet-4-6",
    max_tokens=256,
    messages=[{"role": "user", "content": "Say hello in one sentence."}],
)

print(message.content[0].text)
```
